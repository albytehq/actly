# actly v1.4.2

Reliability and distribution release: one execution engine, true CJS, validated observability, 4.5× faster policy path, 21% smaller tarball. See [MIGRATION.md](./MIGRATION.md) for the 1.3→1.4 guide.

This release follows a full external code review of v1.3.0 that logged 27 findings (3 critical, 7 documentation-vs-implementation, 9 medium, 8 minor), all fixed and regression-tested — followed by a pre-release audit pass that logged 9 more findings on the restructured codebase (double `onFinalFailure` on a failing fallback, `durationMs` excluding the fallback runtime, `fallback: {}` resolving as success, a user-thrown `HedgeTimeoutError` triggering a phantom hedge, `timeoutPolicy({ms: Infinity})` clamping to a 1 ms fire, `cachePolicy({ttl: 0})` becoming an infinite cache, silent coercion in the standalone policy factories, a 1 ms watchdog busy loop on `NaN`/`Infinity`, and unvalidated dedupe options). All 9 are fixed and runtime-verified. Test count grew from 633 to 717. Every shipped artifact was additionally verified from a clean registry install (CJS and ESM consumer smoke tests).

## Headlines

- **Hedge winner no longer aborted** — the v1.3.0 fix for BUG-CORE-015 only covered `inside-retry`; the default `outside-retry` placement still cancelled the winner's downstream side-effects. One shared hedge race now serves both placements.
- **True CJS on every Node 20+** — the 1.3 CJS entry `require`d ESM files and only worked on Node 22.12+/20.19+. 1.4 ships a standalone minified CJS bundle; the 27 dead `.cjs` interstitials (121 KB) and stale `dist/state` artifacts are gone.
- **Error names survive minification** — minifiers rename classes; every concrete error class pins its instance name, so `error.name` and `toJSON().name` report real names (`TimeoutError`, not `"U"`) in both shipped bundles.
- **Observability validation shipped** — unknown hook names throw at call time. (The 1.3.0 release notes claimed this; it was not implemented. Now it is, with regression tests.)
- **4.5× faster full-options path** (20.98 → 4.68 µs/op), ~25% faster cache hits, shared never-aborted fast-path signal, frozen-options policy cache, scoped-act fast path.
- **66.1 KB tarball** (was 84 KB). 209 KB unpacked (was 400 KB). 43 package files (was 152; dist 37). Minified single-file ESM and CJS bundles; `dist/` no longer committed to git.

## Contract changes

1. Programmer errors (invalid key/options, unknown observability hooks) now throw **synchronously** from `act()` — as README 1.3.0 already documented. Runtime failures still always resolve.

## Public API additions (additive)

- Policy factories exported: `retryPolicy`, `timeoutPolicy`, `totalTimeoutPolicy`, `dedupePolicy`, `cachePolicy`, `circuitBreakerPolicy`, `bulkheadPolicy`, `rateLimitPolicy`, `noopPolicy` — all validating their options at construction, identically to `act()`.
- `retry.acceptResult` (non-inverted spelling of `shouldRetryResult`).
- `OBSERVABILITY_HOOKS` (valid hook names).
- `FinalFailureEvent.fallbackError` — a failing fallback is detectable without changing the surfaced error.

## Deprecations (removal in 2.0)

- `retry.shouldRetryResult` → `acceptResult`
- `acquireController` / `releaseController` / `poolSize`

## Performance

- Fast path (no options): **~687k ops/sec** (1.46 µs/op) — no regression; v1.3.0 measured ~695k (1.44 µs/op), within noise.
- Cache hit: **~750k ops/sec** (1.33 µs/op) — v1.3.0 measured ~559k (1.79 µs/op). The ~700k figure quoted in the 1.3.0 notes was stale.
- Full-options path (timeout + totalTimeout): **~214k ops/sec** (4.68 µs/op) — v1.3.0 measured ~48k (20.98 µs/op). 4.5×.
- `act()` with an external signal: ~447k ops/sec (unchanged).
- Frozen options objects are policy-cached in a WeakMap: zero allocation per call for shared config. Non-frozen options are never cached, so mutation stays safe.
- The fast path passes a shared never-aborted signal instead of allocating an `AbortController` per call.
- Scoped `act()` (`withStore`) gained the no-options fast path it was missing.

Measured with `npm run bench` on Node 24.19.0, 100k iterations per case.

## Fixes from the external review

Critical: hedge winner abort (both placements), CJS distribution, observability validation. Medium: single execution engine for act/scopedAct (230-line duplication gone), store-contract typing for `createHealthCheck`, `dedupePolicy({enabled:false})` pass-through, `AttemptEvent` post-settle fields, dead abortPool, stale dist artifacts, bulkhead construction validation, scoped fast path, decorator key collisions. Minor: sleep listener leak, hook-error logging opt-in (`ACTLY_LOG_HOOK_ERRORS=1`), unified message sanitization, drain timeout validation, breaker state TTL, stricter `isActlyError`, rate-limit clock-jump guard. Documentation: bulkhead fail-fast default, runnable `noopPolicy` example, `inflightTtl` JSDoc, size numbers generated by `npm run size`, flat test layout, benchmark description, sync-validation contract. A registry-install consumer smoke test additionally caught the `dedupe` object form being a silent no-op in `act()` (the same behavior since at least 1.3.0) — `dedupe: { inflightTtl }` now enables unless `enabled: false`, matching every other policy and the standalone factory.

## Verification

- Stress torture passed: 10k fast-path calls, 10k policy calls, 5k abort storm, 500 hedge stampede, drain accounting, 1000 scoped stores, +2 MB heap after 60k calls, zero listener warnings.

# actly v1.3.0

Hardening release. Smaller tarball, more policies, deeper audit. 6 breaking changes (see [MIGRATION.md](./MIGRATION.md)).

A line-by-line audit across core, policies, utils, stores, types, errors, and observability turned up 61 bugs. All fixed. Test count grew from 609 to 633.

## Headlines

- **61 audit bugs fixed.** Contract violations on the error path, listener leaks, timer leaks, memory leaks, NaN propagation, circuit breaker correctness, watchdog spam, and a broken error taxonomy. See [CHANGELOG.md](./CHANGELOG.md) for the full list with bug IDs.
- **8 Cockatiel-parity features.** `shouldRetryResult`, `timeout.strategy: 'cooperative'`, `circuitBreaker.strategy: 'count'`, `retry.backoffFn`, `retry.dangerouslyUnref`, `noopPolicy()`, `@usePolicy(options)`, `./testing` subpath.
- **7 stability features.** Per-scope health, `drainAll`, periodic probe, resource budget, `onBackpressure`, watchdog, `memoryPressureCleanup`.
- **57 KB tarball** (was 91 KB). 287 KB dist (was 435 KB).

## Breaking changes

1. Hedge cancels the losing promise via `AbortController`. Set `hedge.keepLoser: true` for the old behavior.
2. Hedge placement defaults to `outside-retry`. Set `hedge.placement: 'inside-retry'` for the old behavior.
3. `dedupe.inflightTtl: 0` now throws. Use `inflightTtl: 1` or omit.
4. `defaultShouldRetry` skips per-attempt `TimeoutError`. Override with `shouldRetry: () => true`.
5. Default `inflightTtl` is 5 minutes (was `Infinity`). Pass `Infinity` explicitly for the old behavior.
6. `observability` shape is validated. Typos in hook names throw at call time.

See [MIGRATION.md](./MIGRATION.md) for before/after code examples.

## Public API additions (additive)

- `isActlyError(e)` realm-safe predicate
- `ActlyError.toJSON({ redact?: boolean })` opt-in message redaction
- `HedgeTimeoutError` now extends `ActlyError`
- `ExecutorInput` and `ObservabilityContext` re-exported from `index.ts`
- `ActlyFailedBy` literal union type
- `TenantStoreOptions.maxTenants` with LRU eviction
- `LIMITS.MAX_HEDGE_DELAY_MS` and `LIMITS.MAX_TENANTS`
- `waitForObsHook` returns a Promise with `.cancel()` for test cleanup

## Performance

- Fast path: ~680k ops/sec (no regression)
- Cache hit: ~700k ops/sec (no regression)
- Slow path: marginal improvement from const caching, lazy allocation, in-place filters
- `usePolicy`: dynamic `import()` cached as a top-level Promise
- `safeCall`: `IS_DEV` flag cached at module load
- `monotonicNow()`: `performance.now()` for sub-microsecond monotonic durations
